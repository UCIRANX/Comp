# راه‌اندازی بات فشرده‌سازی ویدیو روی Render.com

کد اصلی (`bot.py`) هیچ تغییری نیاز نداشت — از قبل پورت رو از متغیر محیطی
`PORT` می‌خونه، که دقیقاً همون چیزیه که Render خودش تزریق می‌کنه. فقط
`Dockerfile` کمی تمیز شد و یه `render.yaml` برای دیپلوی راحت‌تر اضافه شد.

## قدم ۱: گرفتن اطلاعات لازم (یک‌بار، رایگان)

1. برو به **my.telegram.org** → وارد شو → **API Development Tools** →
   یه اپ بساز → `api_id` و `api_hash` رو یادداشت کن.
2. توی تلگرام برو پیش **@BotFather** → `/newbot` → توکن بات رو بگیر.

هیچ‌کدوم از این‌ها نیاز به کارت بانکی ندارن.

## قدم ۲: آپلود کد به گیت‌هاب

فایل‌های این پوشه (`Dockerfile`, `bot.py`, `start.sh`, `requirements.txt`,
`render.yaml`) رو توی یه ریپازیتوری گیت‌هاب (می‌تونه Private باشه) قرار بده.
Render مستقیم از گیت‌هاب دیپلوی می‌کنه.

## قدم ۳: ساخت سرویس در Render

1. وارد **dashboard.render.com** شو (ثبت‌نام فقط با ایمیل/گیت‌هاب، بدون کارت).
2. **New → Web Service** → ریپازیتوری‌ت رو انتخاب کن.
   - چون `render.yaml` توی ریپو هست، Render خودش تنظیمات رو پیشنهاد می‌ده؛
     فقط تایید کن (Environment باید خودکار روی **Docker** بیفته).
3. توی بخش **Environment Variables** این‌ها رو دستی پر کن:
   - `API_ID`
   - `API_HASH`
   - `BOT_TOKEN`
   - `ALLOWED_USER_IDS` (اختیاری — آیدی عددی خودت، تا کس دیگه‌ای نتونه از بات استفاده کنه)
4. **Instance Type** رو روی **Free** بذار.
5. **Create Web Service** رو بزن. اولین بیلد چون `telegram-bot-api` از سورس
   کامپایل می‌شه، **۱۰-۲۰ دقیقه** طول می‌کشه — طبیعیه، صبر کن.

## قدم ۴: نکته‌ی مهم درباره‌ی خواب رفتن (چون بات polling هست، نه webhook)

این بات با روش **long polling** کار می‌کنه (خودش مدام از تلگرام سوال می‌کنه
"پیام جدید داری؟")، نه webhook. این یعنی وقتی Render سرویس رایگان رو بعد از
~۱۵ دقیقه بی‌فعالیتیِ HTTP می‌خوابونه، **هیچ درخواستی از تلگرام به سمت Render
نمیاد که خودش سرویس رو بیدار کنه** — چون تلگرام منتظر جواب بات می‌مونه، نه
برعکس.

دو راه داری:

**راه ۱ (ساده‌تر، مناسب مصرف نیم‌ساعته‌ی روزانه‌ی تو):**
قبل از اینکه بخوای از بات استفاده کنی، یه بار آدرس سرویس رو توی مرورگر گوشیت
باز کن (چیزی شبیه `https://video-compress-bot.onrender.com/health`). این کار
کانتینر رو بیدار می‌کنه (۳۰-۶۰ ثانیه طول می‌کشه)، بعدش می‌تونی عادی توی
تلگرام باهاش کار کنی. پیام‌هایی که موقع خواب فرستاده بشن گم نمی‌شن، فقط تا
بیداری بات توی صف تلگرام می‌مونن.

**راه ۲ (بات همیشه بیدار بمونه):**
یه مانیتور رایگان توی **UptimeRobot** یا **cron-job.org** بساز که هر ۵ دقیقه
آدرس `/health` رو پینگ کنه. این باعث می‌شه سرویس هیچ‌وقت نخوابه. توجه: پلن
رایگان Render سقف ۷۵۰ ساعت رایگان در ماه داره؛ اگه فقط همین یه سرویس رو
داری، ۲۴ساعته بیدار نگه‌داشتنش دقیقاً همون سقف رو پر می‌کنه (تقریباً کل ماه)
و مشکلی پیش نمیاد.

## بقیه‌ی رفتار بات دقیقاً مثل قبله

- `/settings` برای تغییر پیش‌فرض‌ها (فرمت خروجی، CRF، حداکثر ابعاد)
- `/queue` برای دیدن و لغو کارهای در صف
- حداکثر حجم فایل با Local Bot API Server حدود ۲ گیگابایت
- پردازش‌ها سریال و یکی‌یکی انجام می‌شن
- دیسک کاری (`/data/work`) موقتیه و بعد از هر پردازش پاک می‌شه — نیازی به
  Persistent Disk پولی نیست
